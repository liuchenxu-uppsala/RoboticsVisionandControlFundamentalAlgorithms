## 5.1 Introduction to Reactive Navigation(反应式导航)

反应式导航:不建立/不依赖地图,只根据当前传感器读数做局部决策("边走边看"),没有全局最优性保证。

### 5.1.1 Braitenberg Vehicles

- 双侧传感器(如光强)直接、简单地映射到左右轮速度差,不经过"感知-规划-控制"这种显式流程
- `theta_dot = (left_sensor - right_sensor) * K`,注意传感器左右不要接反(练习中出现过这个符号错误,导致车往光源反方向跑)

### 5.1.2 Bug2 Algorithm

- 核心思路:先定义一条"m-line"(起点到目标的直线),沿m-line直走;碰到障碍物就切换成"沿墙走"(wall-following),直到重新碰到m-line且比切入点离目标更近,再切回直走
- 手写实现wall-following时踩了不少坑(m-line浮点误差导致重复点、8方向right-hand-rule判断反、4方向卡死震荡),最终改用roboticstoolbox自带的`Bug2`类在真实`house.mat`地图上跑
- 反应式导航没有全局视野,路径长度远不如后面的全局规划方法(同一张房子地图上,Bug2走了1307步,Distance Transform只需338步)

## 5.2 Introduction to Map-Based Navigation(基于地图的导航)

两种地图表示方式:

- **拓扑图(topological graph)**:节点=地点,边=连通关系+代价,适合5.3的图搜索算法
- **占据栅格(occupancy grid)**:整张地图离散成格子,每格标记"能不能走",适合5.4的算法

## 5.3 Planning with a Graph-Based Map(图搜索)

| 算法 | frontier结构 | 扩展依据 | 保证 |
|---|---|---|---|
| BFS | FIFO队列 | 先进先出 | 边数最少(不考虑边权重) |
| UCS | 按累计代价g(n)排序的优先队列 | g最小者优先 | 代价最优 |
| A\* | 按f(n)=g(n)+h(n)排序的优先队列 | f最小者优先 | 代价最优(前提h admissible) |

- **admissible(可采纳)**:启发式h(n)永远不能高估真实剩余代价,否则A\*会漏掉真正的最优解;欧氏距离(直线距离)对大多数场景是admissible的,因为绕障碍物走只会更远不会更近
- **Minimum-Time Path Planning**:如果要用A\*求"最短时间"路径,h(n)必须用"假设全程用车辆能达到的最大速度"来换算距离到时间,否则容易高估剩余时间,破坏admissible性质
- 手动实现pgraph图时,`add_edge`要传`cost=`,`add_vertex`要传`coord=`(A\*算heuristic要用坐标算欧氏距离),否则报错

Demo: `5_3_graph_search_algorithms.py`

## 5.4 Planning with an Occupancy-Grid Map

### 5.4.1 Distance Transform

- 输入:纯二值occupancy grid(0=free,1=obstacle),不需要人工指定任何代价
- 算法:从目标点开始像波纹一样向外扩散(wavefront/brushfire),给每个能到达的自由格子标上"绕开障碍物之后到目标的最短距离"(实数,不是0/1);到不了的格子标nan
- 找路径:从任意起点出发,每一步走向"距离值最小"的相邻格子("沿距离场下坡"),直到distance=0(目标)
- 两种距离度量:Euclidean(横竖=1,斜对角=√2) vs Manhattan(横竖=1,不许斜走)
- 迭代式算法,每次迭代O(N²),房子地图(596×397)需要571次迭代;**目标一变必须整个重新算**(没有任何"依赖关系"记录,只能重新发一次水)
- 障碍物可以按机器人实际尺寸"膨胀(inflate)",避免规划出机器人物理上过不去的窄路

Demo: `5_4_1_distance_transform.py`

### 5.4.2 D\*(Dynamic A\*)

- 把occupancy grid转成图,每个自由格子是一个顶点,边权重c由costmap定义(横竖=1、斜对角=√2、障碍=∞,也可以泛化成任意正实数代价,不局限于二值)
- `plan(goal=...)`阶段:从目标出发用A\*-like搜索(本质是Dijkstra式的优先队列扩展),给**每个**顶点提前算好两样东西:
  1. g(n) = 到目标的累计最短距离
  2. backpointer = 从n出发下一步该走到哪个邻居(这是D\*比Distance Transform**多存**的东西)
- 在均匀代价的网格上,D\*算出来的g值和路径,跟Distance Transform的结果**完全一致**——区别不在结果,在"算法过程中留没留下依赖关系的记录"
- `query()`阶段:直接沿着backpointer查表走,不用重新搜索
- **增量重规划**:地图局部代价变化时(如`sensorfunc`模拟门被堵),D\*能反查"谁的backpointer原来经过了这个变化点",只重新计算这一小撮受影响的顶点(实测约占全量规划的12%),不用像Distance Transform那样整个重算
- **目标变了 vs 地图变了 是两件不同的事**:目标变,D\*和DT一样都要整个重新plan;只有"地图局部变化、目标不变"时,D\*的增量优势才生效

Demo: `5_4_2_dstar.py`

## 5.5 Planning with Roadmaps

要解决的问题:DT/D\*的规划阶段(plan)锚定在一个特定目标上,目标一换就要重新做一次昂贵的全图计算。Roadmap方法把"建图"和"查询"彻底解耦——建一次固定的路网,之后随便换起点终点,只需要便宜的query。

### 两种建路网方式

- **Voronoi骨架(图像细化/thinning)**:把自由空间"均匀腐蚀"成一条条只有一格宽、处处离障碍物等距的骨架线,计算量大(跟DT一个数量级),第11章才细讲内部算法,这里只需要理解"为什么这条线能当路网用"
- **PRM(概率路图)**:随机撒点,落在障碍物里的丢弃,尝试把每对点用直线连起来(直线穿障碍物则不连),边代价=直线的欧氏距离

### PRM完整流程

**建图阶段**(跟起点终点完全无关):
```python
prm = PRMPlanner(occgrid=floorplan, seed=0)
prm.plan(npoints=300)   # 点数不够会导致图不连通(多个components),需要加点
```

**查询阶段**(三段拼接,对应"走到最近车站→坐火车→走到目的地"):
1. 起点 → 路网上离它最近、且直线可达的顶点("入口",现算,不是预先固定的)
2. 在路网图上用A\*找到"出口"顶点的最短路(路网虽然固定,但A\*本身现搜,因为图很小、代价低,不需要像D\*那样提前存好所有顶点的g值)
3. "出口"顶点 → 真正的目标(直线)

```python
path = prm.query(start=places.br3, goal=places.kitchen)
```

### PRM的trade-off

- 每次随机撒点不同 → 结果不可复现(除非固定seed)
- 图可能不连通(components > 1),起终点分处两个孤岛会直接报错,只能重跑/加点
- 窄通道(走廊)很容易被随机采样"漏采"
- 路径不如DT/D\*平滑,可能有不必要的绕路

Demo: `5_5_1_prm.py`(官方API,真实房子地图) + `5_5_2_prm_manual.py`(手写复现建图+查询两个阶段,验证内部原理)

## 5.6 Planning Driveable Paths(已过一遍概念,demo代码待补)

前面所有规划器(DT/D\*/PRM)给出的路径只保证不撞障碍物,不保证车辆**运动学上真的能走**。核心变量是路径曲率:

```
κ = tanγ / L          (式5.6,回顾4.1的bicycle model)
κ_m = tanγ_m / L       (式5.7,车辆能达到的最大曲率,γ_m=最大转向角)
```

曲率κ和转弯半径R互为倒数(κ=1/R),给定一个另一个就锁死了,不是两个独立参数。

| 方法 | 前进/倒车 | 能否结合障碍物地图 | 曲率是否连续 | 本质算法 |
|---|---|---|---|---|
| Dubins | 只能前进 | 不能 | 不连续 | 几何解析解(L/S/R段组合) |
| Reeds-Shepp | 前进+倒车 | 不能 | 不连续 | 几何解析解 |
| Lattice | 均可配置 | 能(occgrid) | 不连续 | **本质是A\***搜索固定曲率弧线拼成的图 |
| Curvature Polynomial | 前进为主 | 不能 | **连续**(κ(s)=κ₀+as+bs²+cs³,数值优化求解未知系数) | 数值优化 |
| RRT | 均可配置 | 能(多边形障碍,piano mover问题) | 取决于底层用Dubins/RS | PRM式随机采样树 + 图搜索,边替换成Dubins曲线 |

- **非完整约束(nonholonomic)**:约束的是"瞬时能动的方向",不是"最终能到达的位置"——车瞬时只能沿车头方向前进/倒退,但通过一系列maneuver(前进-倒车-转向组合)依然能到达任意(x,y,θ)
- **曲率突变为什么是问题**:转向机构(不管人手还是转向电机)本身有角速度上限,不能瞬间把方向盘打到底,Dubins/Lattice要求κ在{-κ_m,0,κ_m}间瞬间跳变,物理上不可能精确实现
- **Lattice本质**:反复应用3种固定曲率的运动(左转/直行/右转,半径/曲率固定不变),生成一棵配置空间(x,y,θ)里的树/图,内部再用A\*搜索这张图(边代价=弧长)
- **RRT vs PRM**:PRM两点间连直线,RRT两点间连一段Dubins曲线(自动满足曲率约束);RRT"随机采样+连最近节点+碰撞检测+长一步"的核心循环跟PRM建图逻辑一脉相承,只是边的类型换了

## 全程反复验证/推导过的核心要点

1. **坐标(x,y) vs 数组下标[row,col]顺序相反**:坐标先横(x)后纵(y),numpy数组先行(y)后列(x),两者顺序天然是反的,`occgrid[y, x]`才是正确写法
2. **边权重c(静态输入) vs g(n)(算法算出的累计代价)是两个层次的东西**:c是"两个相邻顶点之间"的固定权重,g是"沿某条具体路径累加c"得到的动态结果,不要混为一谈
3. **D\*相比Distance Transform,核心只多存了一样东西**:backpointer(从每个顶点指向"下一步该走哪个邻居"),这是靠"用图搜索算法建图"而不是"纯粹发水扩散"才能顺带记录下来的;正是这一点信息,换来了"地图局部变化时只需局部修复"的增量能力
4. **目标变化 vs 地图局部变化,对D\*的影响完全不同**:目标变,必须整个重新plan(DT/D\*都一样);地图局部变、目标不变,D\*可以增量修复,DT不行
5. **PRM"入口/出口"不是路网固定的属性**,而是每次query()时,现场找"离start/goal最近、直线可达"的顶点动态决定的
6. **PRM的query阶段A\*为什么便宜**:因为PRM的图本身就设计成稀疏的(几十几百个顶点),现搜一次成本很低;D\*的图是整张occupancy grid(几十万顶点),现搜一次代价太高,所以才需要提前存好g值
7. **非完整约束是"瞬时速度方向"的约束,不是"可达配置空间"的约束**——这个区分从4.1差速驱动"能原地转但不是holonomic"就开始反复出现,到5.6依然是同一个概念的延伸
8. **曲率=转弯半径的倒数(κ=1/R)**,两者不是独立参数,给定一个另一个锁死

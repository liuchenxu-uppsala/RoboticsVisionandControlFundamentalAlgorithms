## 7.1 Forward Kinematics

### ET / ETS(Elementary Transformation / Sequence)
- **ET**:最小的运动学链条单元,要么是关节(变量,如`ET.Rz()`),要么是固定连杆(常数,如`ET.tz(L1)`)
- **ETS**:多个ET用`*`连接成的一条完整链条,本质上是"关于关节角度q的函数",代入具体角度才能算出位姿
- **动坐标系语义**:`*`左边先写的,是先发生的动作(顺序和物理发生顺序一致,和我们最早"固定系离点最近先发生"是相反的规则,ET链条属于"动系"场景)
```python
e = ET.Rz() * ET.Ry() * ET.tz(a1) * ET.Ry() * ET.tz(a2) * ET.Rz() * ET.Ry() * ET.Rz()
e.n           # 关节数量
e.structure   # 'RRRRRRR' 这种关节类型简写(R=旋转,P=移动)
e.joints()    # 列出所有关节(不含固定连杆段)
e.fkine(q)    # 代入关节角度q,求末端位姿(SE3对象)
e.teach(q)    # 交互式可视化(需传入初始q)
```

### 层级关系(从小到大)
```
ET(单个变换) → ETS(一串ET,一条链) → Link(带ETS的连杆对象) → Robot/ERobot(整台机器人)
```

### Link对象(以连杆为中心建模)
```python
link1 = Link2(ET2.R(), name="link1")
link2 = Link2(ET2.tx(a1) * ET2.R(), name="link2", parent=link1)
```
- 每个Link,记录"从父连杆,经过什么变换,到达自己"+"父连杆是谁"

### 分支机器人(Branched Robots)
- 一条连杆有多个"孩子"(不是直线链条,是树状结构)
- 典型例子:机械臂主链条(直线)+ 末端夹爪的两根手指(分支)
- 实践建议:通常不把夹爪手指纳入主IK链条,而是简化成一个"工具中心点(TCP)",手指开合作为独立自由度单独控制

### URDF(统一机器人描述格式)
- 厂商/社区提供的标准XML文件,包含关节位置、转轴方向、连杆长度、（可选）3D网格、惯量等信息
- **不需要自己手写ET链条**——库自动解析文件,组装出完整的ETS/ERobot
```python
urdf, *_ = ERobot.URDF_read("path/to/xxx.urdf.xacro")   # 半成品:解析出Link列表
robot = models.URDF.UR5()                                 # 一步到位:库内置的现成机器人
robot.plot(robot.qr, backend='swift')   # Swift后端才支持逼真3D渲染(注意DHRobot不支持swift)
robot.teach(q, backend='swift')          # 交互式+逼真渲染
```

### D-H参数(经典方法)
| 参数 | 含义 | 旋转关节时 | 移动关节时 |
|---|---|---|---|
| a | 相邻两转轴的公垂线长度 | 常数 | 常数 |
| α | 相邻两转轴的夹角 | 常数 | 常数 |
| d | 同一转轴上,公垂线间的偏移 | 常数 | **变量** |
| θ | 绕该轴,公垂线间的夹角 | **变量** | 常数 |

- 编号从0开始:N个关节(0~N-1),N+1个连杆(0~N),连杆0=base(固定底座)
- 标准公式:`^(j-1)T_j = Rz(θj)·Tz(dj)·Tx(aj)·Rx(αj)`
- ⚠️ **标准D-H vs 改进D-H(Modified/Craig 1986)**:参数名字一样,但坐标系摆放规则和公式顺序不同!拿到参数表必须先确认是哪种约定，不能直接套标准公式
  - 改进D-H公式：`^(j-1)T_j = Tx(a_{j-1})·Rx(α_{j-1})·Rz(θj)·Tz(dj)`（下标也变了，是"上一个关节"的a,α）

### 建立运动学模型的替代方法(7.5.2)
- 不用死抠D-H的公垂线/坐标系规则，直接按物理直觉"沿链条走一遍"，记录每一步的方向和距离，翻译成ET链条
- 适合有CAD图纸但没有现成D-H表/URDF的情况

## 7.2 Inverse Kinematics

### 解析解 vs 数值解
| | 解析解(`ikine_a`) | 数值解(`ikine_LM`) |
|---|---|---|
| 前提条件 | 6轴 + **球形手腕**(后三轴交于一点) | 通用,任意关节数、任意结构 |
| 速度 | 快 | 慢 |
| 多解处理 | 显式指定(如"lu"=左手肘上) | 靠初始猜测值`q0`间接影响收敛方向 |
| 奇异点附近 | 可能剧烈跳变 | 更"温和"(自带最小范数倾向) |

- **6轴机械臂一般有8种解**：左右手性(l/r) × 肘部朝向(u/d) × 手腕翻转(f/n)
- UR系列**不是**球形手腕(后三轴平行，非交于一点)，只有PUMA/ABB这类经典结构才是

### 欠驱动机械臂(Underactuated,关节数<6)
- 例：SCARA(RRPR结构)，位置3自由度全有，姿态只有绕Z这1个自由度
- 给"物理做不到的姿态目标"求解会失败(如带XY倾斜的姿态)
- 用`mask`参数告诉求解器"忽略做不到的那几个姿态维度，只关心能做到的"
```python
sol = cobra.ikine_LM(TE, mask=[1,1,1,0,0,1])   # 忽略绕X、绕Y姿态误差
```
- mask不是"提前构造可达目标"，而是每次迭代照常算完整误差、把不关心的维度清零，用剩下的驱动调整

### 冗余机械臂(Redundant/Overactuated,关节数>6)
- 例：Panda(7轴)，6个约束(3位置+3姿态) < 7个未知数，解有无穷多
- 用"最小范数约束"从无穷多解中挑一个：关节角度整体数值最小的那组（动作幅度最小）
- `ikine_LM`默认就有这个倾向，不需要额外设置
```python
TE = SE3.Trans(0.7,0.2,0.1) * SE3.OA((0,1,0),(0,0,-1))   # OA=双向量表示法构造姿态
```

## 7.3 Trajectories

### 关节空间轨迹(Joint-Space Motion)
- 先分别IK求起点/终点关节角度，再在**关节角度**层面平滑插值(quintic五次多项式，起点终点速度加速度都为0)
```python
traj = jtraj(sol1.q, sol2.q, t)
traj.q, traj.qd, traj.qdd   # 位置、速度、加速度，各是(N,关节数)数组
```
- 缺点：末端在3D空间走的路径通常是曲线，不受控制

### 笛卡尔空间轨迹(Cartesian Motion)
- 直接在**末端位姿**层面插值成一条直线，再对每个点单独求IK
```python
Ts = ctraj(TE1, TE2, t)      # 一串SE3位姿，沿直线均匀分布
qc = puma.ikine_a(Ts)         # 对每个位姿求解，前一点的解作为下一点的初始猜测(保持解的连贯性)
```
- 优点：末端路径精确是直线，适合避障/精密任务

### 多段轨迹(mstraj)
- 处理一串多个经过点(via points)之间的连续轨迹，自动平滑过渡，可控制最大速度、加速时间

### 轨迹经过奇异点(Motion Through a Singularity)
- 球形手腕ZXZ结构，中间关节q4≈0时，q3和q5的转轴重合(耦合)
- 数学推导：`Rz(q3)·Rx(0)·Rz(q5) = Rz(q3+q5)`，只依赖q3+q5的和，无法单独反解q3、q5
- 此时该方向的Jacobian行列式趋于0(奇异)，`Δq≈J⁻¹Δp`导致极微小的姿态目标变化，被放大成巨大的关节角度跳变
- 数值解法(`ikine_LM`)比解析解法在此更平滑(最小范数倾向)

## 碰撞检测(Collision Detection)

```python
from spatialgeometry import Cuboid
box = Cuboid([1,1,1], pose=SE3.Tx(1.1))   # scale=[长,宽,高]，pose是中心点位姿
panda.iscollided(q, box)                    # 返回True/False
```
- 原理：给机器人和障碍物都套上简化几何形状(长方体/球体等)，检测这些简化形状是否相交，不用精细网格逐一比较(计算量小)
- 需要额外依赖包：`pip install coal`
- Cuboid的`scale`、`collision`是自己特有参数；`pose`、`color`等是从父类`CollisionShape`/`Shape`继承的通用参数

## 排查陌生库函数的方法(实践中反复用到)
1. 直接运行，看报错信息（最快）
2. `help(类名)` 或 `help(类名.__init__)`（比IDE悬浮提示更完整，能看到子类和父类的完整说明）
3. `dir(类名)` 先看有哪些方法/属性
4. 官方文档网站
5. 看GitHub源码（终极手段，一定准确）

常见坑：子类构造函数用`**kwargs`把参数透传给父类，导致IDE/类型文件看不到完整参数说明（父类真正处理这些参数）
